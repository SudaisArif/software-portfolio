# Local original-motion film renderer

New work defaults to real-footage study films (`python3 renderer/study.py`; see `docs/study-format.md`) and human/source speech. The original-motion renderer below is retained. Its macOS voice is archived and now requires explicit `--system-voice-preview`; it is no longer a silent default.

```sh
python3 renderer/render.py --system-voice-preview --output output/sample.mp4
python3 renderer/render.py --system-voice-preview --style editorial --output output/editorial.mp4
python3 renderer/render.py --system-voice-preview --style storytelling --output output/storytelling.mp4
python3 renderer/render.py --system-voice-preview --brief renderer/sample-brief.json --output output/brief-sample.mp4
python3 renderer/render.py --brief renderer/sample-brief.json --narration output/narration.mp3 --alignment output/alignment.json --output output/licensed-voice-review.mp4
```

Requires Python 3.11+, Pillow, NumPy and FFmpeg/ffprobe. macOS `say` is required only for the built-in preview voice. The paired `--narration` and `--alignment` inputs accept prerecorded narration on Linux or macOS and do not invoke `say` or any API. Dependencies can be installed in an isolated virtual environment with `pip install -r renderer/requirements.txt`. The bundled fonts are permissively licensed DejaVu Sans; see `assets/licenses/DejaVu-LICENSE.txt`. The renderer itself makes no paid calls or account connections.

Three visually distinct scenes are implemented: cinematic graphite/bronze animated 3D weights, cream editorial cue/action diagrams, and a navy illustrated athlete running on moving track lanes. All geometry, movement and sound design are original code. The running figure is a schematic vignette, not a real athlete or invented biography. There is no stock footage, borrowed speech or sampled music.

For the built-in preview voice, each spoken segment is rendered separately and measured. For prerecorded narration, exact character timestamps determine each segment's caption start/end. This is segment-level caption display, not word-by-word highlighting. Render output is native 1080 × 1920 at 24 fps, H.264/yuv420p with 48 kHz stereo AAC, fast-start MP4. Audio is normalized toward -16 LUFS with a -1.5 dBTP target. The output includes the MP4, `.json` script/source/rights manifest, `.qc.json` measured technical report, `.srt`, poster and six-frame contact sheet decoded from the actual finished video.

The supplied alignment JSON may be a direct ElevenLabs alignment object or an API response with an `alignment` field. It requires equal-length `characters`, `character_start_times_seconds`, and `character_end_times_seconds` arrays. Join brief segment text with one space when generating narration. Full aligned text must match that script, including punctuation and case; only whitespace differences are normalized. A `normalized_alignment` fallback is accepted only when its text matches exactly. A provider's spelling-out of numbers, removed punctuation or other text changes are rejected instead of being guessed into place. Timestamps must be finite, nonnegative, ordered, nonoverlapping, and inside the decoded audio duration (50 ms codec tolerance). The audio is decoded to 48 kHz mono, mixed with the original sound bed and normalized without trimming silence or shifting timestamps. Input audio and alignment hashes are recorded in the manifest.

The researched sample deliberately treats cue/action planning as an experiment; evidence is mixed and no guaranteed behavioral or medical result is claimed. Research is in `docs/content-research.md` and the output manifest.

**These are local review samples.** The script and finished video require human approval. The installed macOS Daniel voice has not been cleared for commercial distribution and is explicitly marked preview-only. Supplied narration is marked `requires_external_license_verification`; providing a file alone does not establish its license or the speaker's consent. The surrounding production approval pipeline must retain that evidence. The output manifest always says `publishable: false`; technical QC cannot grant rights or editorial approval. Use contracted/licensed narration and approve the final output before any publication. The manifest's zero cost refers only to local rendering, excluding any upstream generation or licensing cost.

For a fast smoke render, append `--preview-seconds 3`; this explicit test mode also permits shorter-than-20-second input audio. Full films require 20–90 seconds. `--poster-only` prepares narration and one still. `--audio-only` prepares narration and the original sound bed. The audio cache is local under `output/.render-cache/`; output should remain out of source control. External narration uses a separate cache identified by its input hashes. If macOS sandboxing causes `say` to return an empty file, the renderer fails visibly. A permitted host invocation of `--audio-only` may be needed before rendering with the built-in preview voice in a restricted environment.

The renderer is an executable prototype. It accepts new scripts with `--brief` (see `renderer/sample-brief.json`), validates segment lengths for the layout, and consumes supplied character alignment. It cannot verify that claimed timestamps correspond acoustically to the actual spoken words, does not perform independent speech recognition or word-level forced alignment, and does not automatically select licensed footage. Provider timestamps and the finished narration need editorial listening review. Do not confuse the distinct rendering styles with a complete automated sports-story reporting pipeline.
